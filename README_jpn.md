> **安全性（safety）とセキュリティの状況：** これは安全システムではありません。保護出力は制御ユニットの停止ラインへの信号であり、その代わりにはなりません。人と機械を守る停止は、駆動を自力で遮断するハードウェアボタンです。出力は、スピンドルが速すぎる・熱すぎるとき、有効にした温度センサーが応答しないとき、このノードが動いていないときに開きます。トークンのないノードは、測定やカメラ表示を求めるすべての要求を拒否します。全体を実機で試すまで頼らないでください。このプロジェクトは独立しており、Bungard Elektronik が作ったものでも、承認・支援しているものでもありません。製品名は、どの機械向けかを示すためだけに登場します。

## 🎯 概要

* **レーザー測定**：ノードはセンサーから複数の読み取りを得て、外れ値を捨て（中央値と中央絶対偏差）、`laser_sigma_max_mm` を超えてばらつく測定や範囲外の測定を拒否し、テーブルまでの距離とばらつきを返します。デスクトッププログラムはこれをテーブルマップの 1 点にします（`Z x y 高さ`、`eh3d-levelling` が読む）。
* **スピンドル**：回転数はセンサー（ホールセンサーまたはスリット付き円盤、1 回転あたりのパルス数は任意）のパルスから求め、パルスが止まるとゼロになります。温度には警告・危険レベル・ヒステリシスがあり、状態がちらつきません。有効にしたのに応答しないセンサーは高温として扱います。
* **保護出力**：スピンドルが止まるべきとき（速すぎ、熱すぎ、センサー無応答）とノードが動いていない間は Low になる GPIO で、リレーまたはフォトカプラを介して制御ユニットの停止ラインに接続します。設定で無効にできます。
* **protect 出力は監視されます：** それを書き込むタスクはタスクウォッチドッグに登録され、ノードの番人が期待するタスクの一覧にも入っています。そのためハングするとチップが再起動し、ピンが入力に戻って停止ラインが開き、出力が開いたままになることはありません。ボードでは動かしていません。
* **カメラとネットワーク**：カメラ映像は `/stream` の MJPEG、読み取り値は `/api/status` で、有線ネットワークポート（SPI 上の W5500）を使います。トークンが測定とカメラを保護します。
* **設定**：調整されたすべての値（ネットワーク、カメラ、レーザー、スピンドル、温度、保護出力）はノードの設定で、フラッシュに保存され Web パネルで編集します。コード内の数値ではありません。範囲外の値は理由付きで拒否されます。
* **IP カメラと同じ形での映像送信**：RTSP（`rtsp://アドレス/stream1`、JPEG over RTP、UDP または TCP 接続内、Digest または Basic のログイン）と ONVIF（レコーダーや管理ソフトがノードを見つけるための WS-Discovery と、プロファイル S のサービス：プロファイル、カメラが出せるサイズ付きエンコーダー、ストリームとスナップショットのアドレス、ユーザートークン）。どちらも設定のユーザーとパスワードを使い、パスワードがなければ何も提供しません。
* **他のノードと同じパネルと更新：** ノードには A.R.M.O.R. のノードおよび EH3D-NODE-BUNGARD と同じ Web パネルがあります（下部に言語選択とサインアウトのあるグループ化メニュー、概要、メインが切れたときの最大3つの予備ネットワークを持つ Wi-Fi ページ、カメラ・ストリーム・レーザー・スピンドルの設定を編集するヘッドページ、ヘルプ、情報、ユーザー、ログ）。ファームウェアスロットの双方向コピーと、このプロジェクトの最新の GitHub リリースからの更新（リリースが公開する SHA-256 を検証し、アドレスはプロジェクト自身のものに限り、管理者だけが実行できます。リリースは署名されていません）にも対応します。ファームウェアの基盤は EH3D-NODE-BUNGARD と共通です。

## 🧩 EH3D での役割

EH3D-NODE-BUNGARD-AUX は Bungard CCD マシンのドリルヘッドのノードで、EH3D-NODE-BUNGARD（機械を駆動するノード）と EH3D-NODE-BUNGARD-HMI（画面）の隣に位置します。ヘッドに載り、カメラで基板を見て、ヘッド下のテーブルを測り、スピンドルを監視します。デスクトッププログラム（EH3D-BUNGARD-GUI、DRILLPRO、ROUTEPRO）はその測定値でテーブルマップ（EH3D-COMMON の `eh3d-levelling`）を作り、ジョブの Z を補正します。EH3D-BUNGARD-GUI はノードに直接または EH3D-SERVER 経由で問い合わせます（ヘッドノードのウィンドウ）。

## ✨ 機能

* **信頼できる測定か、測定なしか：** 複数の読み取り、外れ値の破棄、読み取りのばらつきが大きい・範囲外・数が少ないときは理由つきで拒否します。
* **常時監視されるスピンドル：** パルスからの回転数、警告・危険レベル・ヒステリシスを持つ温度、異常時やノード停止時に自動で開く保護出力。
* **IP カメラのような映像：** ログイン付きの RTSP と ONVIF で、どんなプレーヤー、レコーダー、ONVIF 管理ソフトでも取得できます。カメラはトークン付きの `/stream` で MJPEG としても提供されます。
* **既定で安全：** トークンがなければ測定もカメラもなし。各制限は設定にスイッチがあり、保守的な位置から始まります。
* **2 種類のカメラ、OV2640 と OV5640：** センサーが自分の種類を答え、ノードは設定が許し、そのセンサーが出せる最大のサイズを返します（OV2640 は 1600x1200 まで、OV5640 は 2592x1944 まで）。`/api/status`（`camera_model`）と ONVIF のエンコーダーオプションで報告します。ヘッドページ の `camera_model = auto | ov2640 | ov5640`。Waveshare ESP32-S3-ETH のカメラコネクターのピンが `menuconfig` の既定値です。
* **3 種類の温度センサー：** ワンワイヤの DS18B20、アナログ入力の NTC サーミスター（ヘッドページ の `ntc_series_ohm`、`ntc_r25_ohm`、`ntc_beta`）、スピンドルに触れずに測れる赤外線温度計 MLX90614（レーザーの I2C バス上）。チェックサムと換算はコンピューター上でテスト済みです。
* **カメラ周囲の LED リング：** 1 本の信号線につないだ WS2812 タイプの RGB LED 8 個が、カメラがよく見えるようにヘッド下を照らします。白はカメラ用の光で、明るさは目の感じ方に合わせ、上限を超えることはありません。片側だけ点灯すれば斜光になり、任意の色も指定でき、検査結果を色で示します（緑、赤の点滅、回る青い点、琥珀色、速い赤）。しばらくすると自動で消灯します。`GET` と `POST /api/light`、`GET /api/snapshot` がプログラムに応え、設定はパネルと `head.cfg`（`light_*`）、ピンはファームウェアのメニュー（`AUX_LIGHT_GPIO`）にあります。
* **37 言語：** ノードの Web パネルが対応する言語：英語、スペイン語、イタリア語、ドイツ語、フランス語、ポルトガル語、中国語、日本語、ブルガリア語、クロアチア語、チェコ語、デンマーク語、オランダ語、エストニア語、フィンランド語、ギリシャ語、ハンガリー語、アイルランド語、ラトビア語、リトアニア語、マルタ語、ポーランド語、ルーマニア語、スロバキア語、スロベニア語、スウェーデン語、ノルウェー語、アイスランド語、ウクライナ語、ロシア語、セルビア語、アルバニア語、カタルーニャ語、ガリシア語、バスク語、ブラジルのポルトガル語、カナダのフランス語。 最初の 8 言語以外の 29 言語はモデルによる翻訳で、ネイティブによる確認待ちです。ない文言は英語で表示されます。
* **常に表示される保存バーと設定のバックアップ：** 「保存」と「保存して再起動」は設定のあるページに常に表示され（変更があるまでは説明つきで無効）、「再起動」は管理者がいつでも使えます。システムページはすべての設定をファイルにエクスポートし（Wi-Fiパスワードとトークンを含むため非公開で保管）、何も送信せずにフォームへインポートし直せるので、各ページはそれぞれの「保存」で保存します。ノードのID・名前・ホスト名はインポートでは変更されません。ネットワークページでは名前・タイムサーバー・タイムゾーン・定期再起動も編集でき、予備のWi-Fiネットワークは変更として扱われ、保存時に送信されます。ブラウザ向けに作成。ボードでは未試験です。
* **作業に合わせたレーザー：** VL53L1X には距離モード（短/長）とタイミング予算、小さな点を狙えるよう狭められる受光エリア、中央値から離れた測定値を捨てるフィルター、測定ごとの状態（有効・信号弱・ばらつき大・範囲外）、既知の距離での校正（オフセットとクロストーク。先に管理者が有効にする）があります。センサーではまだ試していません。
* **同じ線上の複数の DS18B20：** ノードは線上の全センサーを検索し（各アドレスの CRC を確認）、アドレスで主軸のものを選びます（`temp_rom`。1 個だけならそれ、複数で未指定なら最初に見つかったものを使い、状態ページで知らせます）。分解能は 9〜12 ビット（`temp_resolution`）で、その分解能に必要な時間だけ待ちます。模擬バスで計算機上の試験済み。実際の線ではまだ試していません。
* **ノイズと回転を区別する回転数センサー：** TCRT5000（反射式、主軸にマークを付ける）は、デジタル出力の割り込み、またはアナログ出力を高速 ADC と、しきい値が信号に追従するシュミットトリガーで読む方式で動きます。主軸の回転能力より速いパルス、1 回転の途中のスパイク、抜けたパルスは除去され、状態にパルスがきれいかノイズ混じりかが表示されます。400 Hz と 1 kHz の模擬パルス列で試験済み。主軸ではまだ試していません。
* **パネルで調整するカメラ映像：** 左右反転、上下反転、明るさ、コントラスト、彩度、自動/手動露出、オートホワイトバランスを、カメラ起動時に OV2640 と OV5640 に適用します（センサーにない設定はそのまま）。カメラではまだ試していません。

## 🔒 セキュリティと安全

| 脅威 | 対策 |
|---|---|
| 速すぎる・熱すぎるスピンドル | 保護出力は `rpm_max` を超えたときと危険温度で開き、ちらつかないようヒステリシスがあります。有効にしたのに応答しない温度センサーは高温として扱います |
| ノードが電源を失う・固まる | ノードがスピンドルを確認するまで出力は Low で、動いていない間も Low のままなので、自力で開く停止として配線する必要があります |
| ネットワーク上の誰かが測定や作業場の閲覧をする | トークンがなければノードは測定とカメラを拒否します。トークンは一定時間で比較され、表示もログもされません |
| 悪い測定を良い測定とみなす | 外れ値は捨て、`laser_sigma_max_mm` を超えるばらつき、範囲、読み取りの少なさは理由つきで測定を拒否します |
| 設定の打ち間違い | 範囲外の値や未知のキーは報告され、安全な既定値が残ります。警告より低い危険温度や逆の範囲は既定値に戻ります |
| ファームウェアやリポジトリの秘密 | 秘密はコンパイルされません。トークンは専用パーティションの設定です |

**防御していないもの：** ノードは安全装置ではありません。保護出力の信頼性は停止ラインまでの配線次第で、ここにあるものは機械で試していません。ネットワークポートは暗号化されていません（作業場ネットワーク上の素の HTTP ポート）。専用のネットワークに置いてください。

## ⚙️ 設定

設定は1つのドキュメントとしてフラッシュに保存され、Web パネルのヘッドページで編集します（パスワードとトークンは書き込み専用で、パネルには表示されません）。キーとその範囲は `head.cfg.example` に記載のとおりで、以前のバージョンの ヘッドページ ファイルはもう読み込まれません。

| 設定 | 既定値 | 範囲 | 内容 |
|---|---|---|---|
| `token` | none | 8 - 64 | アクセストークン。なければ測定とカメラを拒否 |
| `laser_samples` | `7` | 1 - 31 | 1 回の測定の読み取り数（良好なものの中央値） |
| `laser_offset_mm` | `0` | -50 - 50 | 各距離に加算：センサーが工具先端の上にある位置 |
| `laser_sigma_max_mm` | `0.15` | 0.01 - 5 | 読み取りのばらつきがこれを超える測定は拒否 |
| `rpm_pulses_per_rev` | `1` | 1 - 64 | スピンドル 1 回転あたりのセンサーパルス数 |
| `rpm_max` | `65000` | 1000 - 200000 | この回転数を超えると保護出力が開く |
| `temp_sensor` | none | none ds18b20 ntc mlx90614 | スピンドルの温度センサー |
| `temp_warn_c / temp_critical_c` | `55 / 70` | 20 - 200 | 警告と、保護出力が開くレベル |
| `protect_output` | `on` | on / off | 保護出力が動作。作業台でのみオフに |
| `stream_user / stream_password` | `viewer / none` | 8 - 64 | RTSP と ONVIF のログイン。パスワードがなければ誰にも提供しない |

## 🧪 テスト

コンピューター上のテスト（`build.bat` または `./build.sh`、続けて `ctest`）は 2 本のプログラムで、すべて通ります。`test_aux`（103 項目）は、設定ファイル（既定値、値、誤った値、互いに矛盾する制限）、レーザー測定（中央値、捨てられた外れ値、オフセット、不良とされた読み取り、範囲、読み取りなし、大きすぎるばらつき）、スピンドルの回転数（1 回転あたりのパルス、減速するスピンドル、パルスが止まれば停止）、温度（ヒステリシス、故障するセンサー）、保護出力、ネットワークの言葉（リクエスト行、ルート、ヘッダーまたはクエリのトークン、読み取り数、状態と測定の JSON、マップの 1 点の行）を確認します。ファームウェアは対象外です。ビルドはできますが、テストはコンピューター上で動きます。 2 本目のプログラム `test_stream`（100 項目）は映像を対象にします：ログインのハッシュを公開されたベクターと照合（MD5、SHA-1、base64、RFC 2617 の Digest 例）、RTSP リクエストとセッション全体（ログイン、SDP、UDP とインターリーブの転送、play、pause、teardown、誤ったセッション、拒否されるマルチキャスト）、JPEG の RTP ペイロード（最初のパケットの量子化テーブル、順序、マーカー、シーケンスの折り返し）、ONVIF（ディスカバリー、標準の例によるユーザートークン、公開と保護された呼び出し、各サービス、未対応の呼び出し）。 この2つのプログラムに加え、`test_head_settings` がパネルと同じ方法で設定ドキュメントのヘッド部分を読み取り・検査・書き込みし（パスワードとトークンは書き込み専用のまま）、ファームウェア基盤の共通テストが GitHub からの更新、時計、ユーザーを扱います。

ヘッドが実機につながる日のためのセルフテスト：`python tools/selftest.py --host ノード --token TOKEN` がノード（バージョン、状態、設定のエクスポート、予備ネットワーク、温度、回転数、照明、カメラ画像、ストリーム、RTSP、レーザー測定 1 回）を読み、1 ステップ 1 行のレポートを書きます。`--active` と入力による確認があれば、照明リングを 2 秒点灯して元に戻します。レーザーの校正は実行しません。テストは CI でおもちゃのノードを相手に実行されます（`python -I -m unittest discover -s tools -p "test_*.py"`）。手作業の手順は [docs/HARDWARE_CHECKLIST.md](docs/HARDWARE_CHECKLIST.md) にあります。

## 🩺 トラブルシューティング

| 症状 | 対処 |
|---|---|
| 測定が `no_readings` で拒否される | I2C バスに VL53L1X が応答しません。`menuconfig` の SDA と SCL のピン（Waveshare ESP32-S3-ETH ではカメラが GPIO 41 と 42 を使います）と配線を確認してください。応答のそれ以外の部分はテスト済みです。 |
| 測定が `too_noisy` で拒否される | 読み取りのばらつきが `laser_sigma_max_mm` を超えています。ヘッドとテーブルが落ち着くのを待つか、制限を少し上げてください。揺れがないかも確認します。 |
| 測定やカメラに 401 が返る | ヘッドページ に `token`（8〜64 文字）を設定し、ヘッダー `Authorization: Bearer ...` または `?token=` で送ってください。 |
| 保護出力がいつも開いている | 有効にしたのに応答しない温度センサーは高温として扱われます。配線、`menuconfig` のピン、ヘッドページ の `temp_sensor` を確認するか、作業台では `temp_sensor = none` にしてください。 |

## 🗺️ ロードマップと既知の制限

**現時点の既知の制限**

* ボード上では何も動かしていません。ファームウェアはビルドできますが書き込み・試験はしておらず、カメラとネットワークチップのピンはボードの回路図で確認する必要があります。
* レーザー（I2C 接続の VL53L1X、あまり使われていないコンポーネント `grrtzm/vl53l1x_library` を使用）、温度センサー、カメラのドライバーは書かれていますが一度も動かしておらず、ボードで最初に応答するセンサーで誤りが見つかる可能性があります。
* EH3D-BUNGARD-GUI（ヘッドノードのウィンドウ）と EH3D-SERVER がノードに直接またはサーバー経由で問い合わせます。どちらも実際のノードでは未試験です。
* ネットワークポートは素の HTTP です。専用のネットワークに置いてください。
* RTSP と ONVIF は実際のプレーヤー、レコーダー、ONVIF 管理ソフトでは試していません。ボード上のカメラの型番がサイズとピンを決めます。

**次**

* ファームウェアをビルドし、ボードでドライバーを試す。
* EH3D-BUNGARD-GUI、EH3D-SERVER、画面との接続とカメラ表示を追加する。
* 機械の停止ラインに配線した保護出力を試す。
